Executes a given bash command in a persistent shell session, ensuring proper handling and security measures.

All commands run in ${directory} by default. Use the `workdir` parameter if you need to run a command in a different directory.

## Background Job Support

Commands can run in background in two ways:

- **Explicit Background**: Set `background=true` to immediately run as background job
- **Auto-Background**: Commands running longer than 60 seconds are automatically converted to background jobs
- **Job ID**: Each background job gets a unique ID for management
- **Job Tools**: Use job_output, job_kill, and job_list to manage background jobs
- **Auto-Cleanup**: Background jobs are automatically cleaned up after 8 hours

## KISS Principle

This tool follows the Keep It Simple, Stupid principle:
- **No timeout parameter**: Commands never auto-terminate, they run until completion
- **Simple background control**: Just set `background=true` for immediate background execution
- **Automatic conversion**: If a command runs longer than 60 seconds, it's auto-converted to background
- **Focus on core functionality**: No complex timeout management, just background vs foreground execution

## Usage

### Foreground Commands (Default)
Commands run synchronously by default and return output when complete:
```bash
# Quick commands run in foreground
echo "Hello World"
git status
ls -la
```

### Background Commands (Two Ways)

#### 1. Explicit Background
Set `background=true` to immediately run as background job:
```bash
# Explicit background execution
bash(
  command="npm run dev", 
  background=true,
  description="Start development server"
)
```

#### 2. Auto-Background Conversion
If a foreground command runs longer than 60 seconds, it automatically converts to background:
```bash
# This will auto-convert after 60 seconds
bash(
  command="docker-compose up", 
  description="Start services"
)
# After 60s: "Command automatically converted to background job with ID: A1B2"
```

### Managing Background Jobs

#### View Job Output
```bash
# Check job status and output
job_output(job_id="A1B2")

# Follow job output in real-time
job_output(job_id="A1B2", follow=true)
```

#### List All Jobs
```bash
# Show all background jobs
job_list()

# Show only running jobs
job_list(status="running")
```

#### Terminate Jobs
```bash
# Stop a background job
job_kill(job_id="A1B2")

# Force terminate
job_kill(job_id="A1B2", force=true)
```

Before executing command, please follow these steps:

1. Directory Verification:
   - If command will create new directories or files, first use the List tool to verify the parent directory exists and is the correct location
   - For example, before running "mkdir foo/bar", first use List to check that "foo" exists and is the intended parent directory

2. Command Execution:
   - Always quote file paths that contain spaces with double quotes (e.g., rm "path with spaces/file.txt")
   - Examples of proper quoting:
     - mkdir "/Users/name/My Documents" (correct)
     - mkdir /Users/name/My Documents (incorrect - will fail)
     - python "/path/with spaces/script.py" (correct)
     - python /path/with spaces/script.py (incorrect - will fail)
   - After ensuring proper quoting, execute the command.
   - Capture the output of the command.

## Important Notes

- **No timeout parameter**: Commands never auto-terminate based on time. They run until completion or manual termination.
- **Auto-conversion**: Any command running longer than 60 seconds will be auto-converted to background.
- **Background jobs**: Can be managed with job_* tools and persist until completion or manual termination.
- **Resource management**: Background jobs are automatically cleaned up after 8 hours.

Usage notes:
    - The command argument is required.
    - The background parameter determines if command runs in background (true) or foreground (false, default).
    - The workdir parameter sets the working directory. Use this instead of 'cd' commands.
    - The description argument is required. You must write a clear, concise description of what this command does in 5-10 words.
    - If the output exceeds 30000 characters, output will be truncated before being returned to you.
    - Avoid using Bash with the `find`, `grep`, `cat`, `head`, `tail`, `sed`, `awk`, or
  `echo` commands, unless explicitly instructed or when these commands are truly necessary
   for the task. Instead, always prefer using the dedicated tools for these commands:
       - File search: Use Glob (NOT find or ls)
       - Content search: Use Grep (NOT grep or rg)
       - Read files: Use Read (NOT cat/head/tail)
       - Edit files: Use Edit (NOT sed/awk)
       - Write files: Use Write (NOT echo >/cat <<EOF)
       - Communication: Output text directly (NOT echo/printf)
    - When issuing multiple commands:
       - If the commands are independent and can run in parallel, make multiple Bash tool
  calls in a single message. For example, if you need to run "git status" and "git diff",
  send a single message with two Bash tool calls in parallel.
       - If the commands depend on each other and must run sequentially, use a single Bash
  call with '&&' to chain them together (e.g., `git add . && git commit -m "message" &&
  git push`). For instance, if one operation must complete before another starts (like
  mkdir before cp, Write before Bash for git operations, or git add before git commit),
  run these operations sequentially instead.
       - Use ';' only when you need to run commands sequentially but don't care if earlier
  commands fail
       - DO NOT use newlines to separate commands (newlines are ok in quoted strings)
    - Try to maintain your current working directory throughout the session by using
  absolute paths and avoiding usage of `cd`. You may use `cd` if the User explicitly
  requests it.
       <good-example>
       pytest /foo/bar/tests
       </good-example>
       <bad-example>
       cd /foo/bar && pytest tests
       </bad-example>

# Working Directory

The `workdir` parameter sets the working directory for command execution. Prefer using `workdir` over `cd <dir> &&` command chains when you simply need to run a command in a different directory.

<good-example>
workdir="/foo/bar", command="pytest tests"
</good-example>
<good-example>
command="pytest /foo/bar/tests"
</good-example>
<bad-example>
command="cd /foo/bar && pytest tests"
</bad-example>
