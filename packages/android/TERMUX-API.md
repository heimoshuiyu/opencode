# Device MCP compatibility status

Baseline: the 57 `scripts/termux-*.in` entries in [termux-api-package at 9e7f153](https://github.com/termux/termux-api-package/tree/9e7f1531e1aa4a9c1e261a2dbde4de93653c366e/scripts). This compares operations, **not CLI argument or JSON wire compatibility**. MCP names acquire the `android_` prefix in OpenCode. Only the local host connects to this server.

| Upstream command suffix | Current implementation / gap |
|---|---|
| api-start, api-stop | APK lifecycle: selecting local starts the server; the user's stop action ends it. Not two MCP commands. |
| audio-info | `android_audio_info` without arguments still lists input/output devices. `{"view":"capabilities"}` reads Android's output sample rate and frames per buffer, A2DP and wired-headset indicators, and probes default, low-latency and power-saving `AudioTrack` configurations without playing or recording. Each result reports the negotiated sample rate, buffer size in frames and actual performance mode, not a claim that the request was honored. Android 16 emulator MCP instrumentation (`audio-info`) matched independently created tracks: 48,000 Hz / 4,360 frames / mode 0 for all three requests; output property 1,088 frames per buffer. |
| volume | `android_volume({})` lists current and maximum levels for all six streams; upstream `call` is named `voice_call`. Android 16 `volume` checked each entry against `cmd media_session volume --stream ID --get`. After foreground approval, both the MCP receipt and AudioService readback matched: voice_call 3→4, system 5→6, ring 5→6, music 5→6, alarm 6→7, notification 5→6. Refusing the music request left it at 5. Each stream was restored through MCP and the final six-stream snapshot matched the initial one (`INSTRUMENTATION_CODE: -1`). These are system volume indices, not physical loudness measurements. |
| battery-status | `android_battery_status` reads battery presence, technology, level/scale, percent, plug type, health/status, temperature and voltage from the Android battery broadcast. Independent `BatteryManager` properties supply `capacityPercent`, signed instantaneous/average current (µA), charge counter (µAh) and energy (nWh); cycle count comes from the broadcast on API 34+. Unsupported properties are `null`, not zero. `am instrument -w -e scenario battery-status ai.opencode.android.test/ai.opencode.android.KeySmoke` exercised the authenticated MCP handler on Android 16; a 37% unplugged broadcast reported 0°C, while unsupported energy remained null. The fuel-gauge capacity is not an alias of the simulated broadcast level. |

Returns the system mode and brightness read back from Settings. Omitting `scope` retains the window-only behavior (`-1` follows the system). |
